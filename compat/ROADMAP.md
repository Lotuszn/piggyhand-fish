# 兼容路线图（以「不抛弃老版本用户」为目标）

> 立：2026-11-12。前提见 `COMPAT_RULES.md` 规则 21：floor 固定 7.29.10，只向上兼容。
> 本文只回答一个问题：**下一步该往哪投工，才能让 floor 上的用户不被新版本挤掉。**

## 零、先排敌人顺序

老版本用户被抛弃，按发生频率从高到低其实是四件事，不是「适配没做」：

| # | 真实原因 | 现状 | 该不该现在投 |
|---|---|---|---|
| 1 | 用户不更新模块，还装着半年前的 APK | 有 UpdateChecker，无兼容性提示 | **该**，成本最低 |
| 2 | 接口加字段/改名 → 返回 PARAM / NOT_FOUNDED | 归因有了，名字族与模板没落地 | 该，但要最小化 |
| 3 | 宿主 UI 改版 → 点不到入口 | 无锚点层 | 暂缓，先看是否真发生 |
| 4 | 宿主符号重排 → NO_PATH | **已解决**（候选表 + 形状校验） | 已投完，不再加 |

结论：**优先级按「能多早知道问题」排，不按「功能多完整」排。** 第 1 项直接决定你能否在用户骂之前知道出事。

## 一、P0（下个版本就能做，不加抽象层）

### P0-1 能力自检进 CAPS

`Diag.caps()` 现在只报符号。加一段 `features`，每条业务链一个布尔值，判据必须是**可静态验的**，不许发请求：

```json
"features": {
  "coin_balance": {"entry": "ok", "api_seen": true},
  "coin_award":   {"entry": "ok", "api_seen": false},
  "game_task":    {"entry": "ok", "api_seen": true}
}
```

`api_seen` 的来源是这次运行中被 hook 到的真实请求名（`FishMtopHook` 已有 request 捕获），
不是猜。验收：floor 版本上 `features` 全 true；跑一次 COIN 后 `api_seen` 至少 3 条 true。

### P0-2 兼容性横幅

`MainActivity` 首页顶部加一行状态，三态，数据来自 `matrix.json` 内嵌的一份精简副本（assets）：

```
闲鱼 7.29.10(530) · 支持范围内
闲鱼 7.30.0(540) · 未验证，功能可能不全
闲鱼 7.27.x     · 低于支持下界
```

理由：用户不知道自己在什么状态时，任何功能缺失都会被当成「坏了」。这一行把「坏了」变成「已知」。

### P0-3 缺能力时降级，不许整链失败

现状：一条链拿不到入口就整段报 `NO_PATH`。
改成：单条链失败只标记该链 unavailable，其余链继续跑，报告里写 `[NO_PATH] 领奖链不可用`。
验收：人为把候选表改坏一条，COIN 仍能出余额与任务清单，只有领奖列为不可用。

## 二、P1（等真实踩坑后再做，只做最小的）

### P1-1 `Apis.java`：名字族，只包 3 个接口

只包最脆的三个：余额查询、任务列表、领奖。每个一条主名 + 最多两条别名，失败换族重试一次。

```java
static String[] balance() { return new String[]{"point.withdraw.query", "..."}; }
```

其余 100+ 个接口保持直写——它们没坏过，包起来只是负债（规则 20）。
验收：把主名改成不存在的字符串，链仍能靠别名跑通。

### P1-2 `Templates.java`：只对踩过 PARAM 的接口建模板

第一次遇到 `PARAM_ILLEGAL` 时，把那次请求体存成模板 A，改字段后存模板 B，
发送时按「A 失败 → 试 B」。**没有第二次踩坑之前不建。**

## 三、P2（有明确需求才做）

- `anchors`：UI 锚点用正则/文本，禁坐标。只在「真的因为改版点不到」发生过两次后做。
- 远端 delta 配置：自签校验，能不发版修参数。代价是要维护签名与回滚，先不做。

## 四、不做清单（写死，避免反复讨论）

- 不做版本号分支（门禁 R6）。
- 不做「按版本加载不同实现类」的插件化容器。
- 不预先抽象没踩过的层。
- 不为 below_floor 版本（7.28 及更早）加任何候选/模板/分支。

## 五、每次发布的固定动作

1. `python _dev/compat_gate.py` → 必须 0。
2. floor 版本真机跑 `CAPS`，`features` 全 true。
3. 最新版本真机跑 `CAPS` + 一条完整业务链（规则 14 双端验证）。
4. `compat/matrix.json` 更新时间与新条目；`floor.host` 必须仍是 7.29.10。
5. 跑一次导出日志，确认头部的 `# 闲鱼=` 与实测一致。
